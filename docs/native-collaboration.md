# 桌面协作工作流

打开项目后选择菜单 **协作 → 打开协作面板**，或点击右侧“协作”。首次使用需要安装包含该入口的新宿主。

## 实际开发

模型配置可在“设置 → 工具 → AI 服务商”完成：保存密钥后自动获取模型，或点击“获取模型列表”；
从可搜索列表选择模型，也可手填。点击“测试连接”会实际请求所选模型，可能产生 API 用量，但不会发送项目代码。
列表不受支持时仍可手填并测试。点击“用于协作与提交”明确启用当前配置。
Codex / Claude 导入配置保持只读；需要独立修改模型时点击“创建可编辑副本”，再选择模型并启用副本。
服务商、地址、密钥或模型变化后需要重新测试，旧的成功状态不会继续保留。

1. 在现有 AI 设置中配置供应商、模型与密钥（复用 AI 辅助的配置）。打开相关项目文件。
2. 在协作面板填写需求，点击“分析需求，生成计划”。模型接收最多 8 份已打开项目文件的文本，生成待确认草案。
3. 审阅分工、文件与 Java 方法范围。需要调整时展开“编辑计划与文件范围”，修改 JSON 并应用，再确认计划。
4. 配套步骤点击“执行 AI 配套修改”。模型只能返回补丁，没有 shell 或文件工具；Core 拒绝越界补丁，宿主核对原文后写入。写入时所有已打开文档必须没有未保存修改。
5. 核心逻辑在 Lithe 原编辑器中编写。保存后主动交接，点击“AI 分析我的代码”。分析基于已保存的目标源码，返回问题与建议，不自动修改人工代码。
6. 点击“运行项目 Java 测试”使用已有测试工具，结果在测试面板查看。项目测试是用户主动执行的项目代码，独立于受限模型通道。
7. 检查 AI 修改记录和实际测试结果，再人工验收。需要修改可退回；暂停或完成后可撤销最近 AI 修改，其他方法中的人工改动保留，冲突拒绝覆盖。

普通 Agent 对话仍可单独打开，但其工具权限独立于协作计划。复制任务说明不是权限隔离措施。
AI 代码分析不代表编译或测试通过，结果记录也不能代替测试面板的真实输出。

## 独立扩展与回退

导入 `shared/fixtures/collaboration/*.workflow.json` 可以安装开发或维护工作流。先按实际项目调整路径和方法声明，示例不创建源码。
已安装版本在“已安装工作流与历史版本”中选择、回退或移除。相同 ID/版本的内容必须一致，修改包时递增版本；最多保留 30 个版本。
运行中的计划固定自身快照，新增版本不会改变它。完成或明确清除旧计划后再切换；移除库中的版本不会删除当前计划与代码。

无需重打包即可调整步骤、分工、问题、提示词、验收条件、目标文件和方法。新增原生控件、执行工具权限、协议版本仍需升级宿主。
当前是本地 JSON 数据包安装与版本回退，不是在线插件市场，也不加载任意代码插件。

## 中断恢复

会话按项目保存在平台 Application Support，未完成写入另存恢复记录，不写安装包。重启后计划暂停。
出现恢复提示时，若文件都已写完，可“核对并完成上次写入”；部分完成时可“回退未完成写入”。
若源码已被人工或其他程序改动，恢复拒绝覆盖，需要保留现场并处理冲突。恢复前不要删除记录。
未提交的输入框草稿不在重启后恢复。源工作流文件地址不持久化，更新时可重新导入；已安装版本和当前计划会保存。
