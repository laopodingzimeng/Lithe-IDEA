# A 方案：桌面沉浸式人机协作实施计划

本次沿用已确认的 A 方案：左侧项目、中央原有编辑器、右侧协作向导、编辑器下方任务预览。
用户负责核心业务，AI 完成已确认的配套范围。HTML 只作交互参考，产品使用原生桌面视图。

## 交付顺序

1. **找到代码，再生成计划**：复用项目文件目录与文档入口，提供有预算、可关闭的上下文。
   计划说明现有文件与新增文件，业务疑问才交给用户；已有代码的位置由工具定位。
2. **接管与导航**：进入步骤自动打开目标；默认跟随当前任务，手动选择后固定。
   用户编辑时暂停跟随；“我来写”取消当前生成，迟到结果失效；恢复须用户主动操作。
3. **真实执行与预览**：显示等待、生成、校验、写入、失败的实际状态。
   生成草稿不直接改文件，校验完成后由现有文档链路显示真实写入。
   下方任务可收起、展开、固定，并将已写入的文件打开到主编辑器。
4. **独立配套任务**：仅在用户确认的当前步骤内、明确独立的文件范围并发生成。
   相同文件不并发提交；全部结果先通过范围及基线校验，再由一个写入日志提交。
   出错或接管取消整组，避免半份任务被当成成功。旧工作流默认保留串行行为。
5. **A 样式与提问**：右栏保留当前模型、当前步骤、固定输入及主操作。
   解释性问题由只读模型回答，不能通过提问扩大写权限；完整计划、历史和管理折叠展示。
6. **验证与构建**：确定性测试覆盖取消、迟到结果、文件冲突、跟随、并发及恢复。
   更新契约、工程笔记和平台矩阵，通过原生 CI 后集中构建一份桌面安装包。

## 必须保持的边界

- 复用原有编辑器、项目查找、HTTP 服务商和 Rust 范围校验，不引入另一个编辑器或无限权限 Agent。
- 模型未实际返回内容时只能显示等待；收到完整响应后不能用打字动画假装流式生成。
- 未完成、失败和取消的草稿不能写入项目；预览必须明确标记尚未写入。
- 用户未保存的目标文件和生成期间变化的基线都阻止提交；其他文件的人工编辑不应被覆盖。
- 并行生成并不改变计划的串行验收状态机，核心逻辑不会自动委派给 AI。
- 配置与工作流数据可独立更新；新增原生宿主能力仍需升级一次程序。
- 运行时状态沿用平台 Application Support 路径，不写安装包。

## 验收场景

| 场景 | 可观察结果 |
| --- | --- |
| 未手动打开源码，描述维护需求 | 自动提供项目路径与受限代码上下文，计划给出可确认的文件范围 |
| 开始 AI 配套步骤 | 主区自动定位，任务条展示实际执行状态，完成后显示真实代码 |
| 多个独立配套任务 | 小窗分别展示进度，可以固定其中一个；写入和验收仍有一致记录 |
| 用户开始编辑或点击“我来写” | 不再跳走，当前生成失效，迟到响应不会写入 |
| 缩小或放大任务预览 | 主编辑器及未保存内容保留；预览不成为另一份可写代码源 |
| 生成失败、取消或源码被修改 | 有明确原因，没有虚假的“已完成”，可重新执行 |
| 写完核心并交接 | AI 只读分析当前保存内容，未运行的测试不能标记通过 |
| 重启、切换项目、清除计划 | 取消旧任务、隔离状态；重启先暂停，不自动继续写入 |
